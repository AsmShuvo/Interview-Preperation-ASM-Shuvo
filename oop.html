Classes and Constructors

1. Class vs. Object:

A Class is a logical construct; it is a blueprint or template. It creates a new data type but does not occupy memory until used.
An Object has physical reality; it is an instance of a class. It occupies space in memory (specifically, the Heap).

Why is a class logical and an object physical?
Logical: The class defines what an object will be (its attributes and behaviors), but it’s just an idea.
Physical: When you create an object, the system allocates actual memory to store specific data defined in class.

Example:

class Car {       // Logical construct (Blueprint)
   String brand;
   int speed;
   void accelerate() { speed += 10; }
}


Car myCar = new Car(); // Physical reality (Object created in memory)?

Class: Defines what a "Car" is.
Object: Represents an actual car with data (e.g., brand = "Toyota", speed = 50).

Objects are characterized by three essentials:

  • State: The value from its data type (the data held in variables).
  • Identity: Distinguishes one object from another (essentially the memory address).
  • Behavior: The effect of data-type operations (methods).

Instance Variables and Methods

The variables defined within a class not declared with the static keyword are called instance variables

2. Memory Management & The new Keyword

Declaring a variable does not create an object.

Box mybox;             // 1. Declare reference to object
mybox = new Box();     // 2. Allocate a Box object

Line 1: mybox is a reference variable. Currently, it doesn't refer to a real object.
Line 2: The new keyword dynamically allocates memory at run time and returns a reference (address) to it. mybox now holds that address.

Why don't we use new for int or char? → Java’s primitive types are "normal" variables, not objects, for the sake of efficiency.

Reference Sharing (The "Remote Control" Analogy):

If you assign one object reference to another, you are not copying the object. You are copying the reference. 

Box b1 = new Box();
b1.width = 10;


Box b2 = b1;  // b2 now points to the SAME object as b1
b2.width = 30;


System.out.println(b1.width); // Output: 30
// Changing b2 affects b1 because they are the same object.

Null Assignment: If b1 = null;, the reference is cut. b1 points to nothing. However, if b2 was pointing to that object, b2 still refers to it. The object is not destroyed until any reference point to it.

Garbage Collection:

Java automatically handles memory deallocation. When an object has no references pointing to it, it becomes eligible for Garbage Collection.
It happens sporadically (not immediately).
We don't need to explicitly destroy objects.

3. Methods

General Form

type name(parameter-list) {
  // body
}

Parameter: The variable defined in the method (e.g., int i).
Argument: The actual value passed when calling (e.g., 100).

Variable Scope & The this Keyword

It is illegal to have two local variables with the same name. However, a local variable(functional scope. Eg: constructor parameter) can have the same name as an instance variable (this "hides" the instance variable).
We use this to resolve the collision. this refers to the current object. 

Box(int width) {
    this.width = width; // 'this.width' is the instance var, 'width' is the parameter
}

Note: this cannot be used in static methods (because static methods belong to the class, not an instance).

Method Overloading (Polymorphism):

Multiple methods can share the same name if their parameter lists differ.

  • Rules: Same class, same name, different parameters (type or number or order).
  • Return Type: Changing only the return type is not sufficient for overloading.

Java's Logic: It executes the version where parameters match the arguments.
Recursion: A method calling itself. Each call creates new local variables on the stack. As calls return, the stack "unwinds."

4. Passing Parameters: Reference vs. Value

Java creates a copy of the argument when passing it to a method.

  • Primitives: Passed by Value. The method gets a copy; the original is untouched.
  • Objects: Passed by Value of Reference.
    The method receives a copy of the reference.
    If you modify the object's data (e.g., car.speed = 100), the original object changes.
    If you reassign the reference itself (e.g., car = new Car()), the original reference outside remains unchanged. *** 
public static void changeReference(Car car1, Car car2) {
    car1.name = “honda” //possible
    car1 = car2;  // This only changes the LOCAL reference variable
}
// The original 'car1' back in main() still points to its original object.

5. Constructors

A constructor initializes an object immediately upon creation.

  • Name: Must match the Class name.
  • Return Type: None (not even void). It returns the object reference implicitly.
  • Execution: Called automatically when new is used.

Types of Constructors:

  • Default: If you write no constructor, Java provides a no-arg default one.
  • Parameterized: Initializes fields with specific values.
  • Overloaded: You can have multiple constructors with different parameters.

Constructor Chaining (this())

One constructor can call another in the same class to reuse code. 

Box() {
    this(10, 20); // Calls Box(int, int)
}

Extended Example:

class Student {
    String name;
    int age;
    double marks;
    // Constructor 1
    public Student(String name) {
        this.name = name;
        System.out.println("Name: " + name);
    }
    // Constructor 2
    public Student(String name, int age) {
        // Calling Constructor 1
        this(name);
        this.age = age;
        System.out.println("Age: " + age);
    }
    // Constructor 3
    public Student(String name, int age, double marks) {
        // Calling Constructor 2
        this(name, age);  
        this.marks = marks;
        System.out.println("Marks: " + marks);
    }
}
public class Main {
    public static void main(String[] args) {
        // Creating an object of Student class using Constructor 3
        Student student = new Student("John", 20, 85.5);
    }
}

Note: this() must be the first statement in the constructor else, we’ll get error
Super: To call a superclass constructor, use super() this also should be the first statement in the constructor.

6. Nested Classes

Classes defined within the scope of another class.

1. Static Nested Class

  • Associated with the outer class, not an instance.
  • Can only access static members of the outer class.
  • Access: Outer.StaticNested obj = new Outer.StaticNested();

2. Inner Class (Non-Static)

  • Associated with an instance of the outer class.
  • Can access all members (even private) of the outer class.
  • Access: You need an outer object first.
    OuterClass obj = new OuterClass();
    OuterClass.InnerClass obj2 = obj.new InnerClass();

3. Local Inner Class

  • Defined inside a method.
  • Can access local variables only if they are final or effectively final (assigned only once).
  • Cannot be accessed from outside the method.

4. Anonymous Inner Class

  • A class without a name, instantiated in a single statement.
  • Used for overriding methods or implementing interfaces on the fly. 
A obj = new A() {
    public void show() { System.out.println("Anonymous override"); }
};

The .class file

During compilation, every class is put into its own .class file containing bytecode. The source filename must match the public class name so Java can find the corresponding .class file.

Memory Structure (Simplified)

  • Method Area (Metaspace): Stores class definitions/code.
  • Heap: Stores Objects.
  • Stack: Stores reference variables and method calls.

System Class

System.out: System is a class, out is a static variable representing the output stream to the console.

Strings & Arrays

  • Arrays: Are implemented as objects in Java.
  • Strings: Are objects. They are immutable (cannot be changed once created).

Notes on Edge Cases

  • Constructors in Interfaces? No, interfaces are not instantiated.
  • Constructor without super() call? It implicitly calls super() (the parent class constructor).
  • Null Pointer Exception: Occurs if you try to use the . operator on a reference that is null.

Encapsulation 💊

Definition: Encapsulation is the process of wrapping up data (variables) and methods (functions) into a single unit—usually a class—and controlling access to them.

The Analogy: Think of it like a medical capsule. The medicine (data) is wrapped inside a container so it’s kept together and safe from outside interference.
Key Goal: Data Hiding & Security.

How We Achieve Encapsulation

The basis is the Class, but specific techniques enforce it:

1. Data Hiding & Access Control 🔒

  • Private Variables: Make variables private so they cannot be accessed directly from outside.
  • Getters & Setters: Provide public methods to view or modify data. Inside these, you can add validation logic.

2. Logical Grouping

  • Static Nested Classes: Group related functionality.
  • Packages: Provide modularity and organization.

Encapsulation vs. Abstraction 🎭

Feature Encapsulation Abstraction
Focus Implementation Level (How it works internally) Design Level (What user sees)
Goal Security: Protecting data Simplicity: Hiding complexity

Inheritance

NOTE: Polymorphism does not apply to instance variables.

What is inheritance in Java?

Inheritance is the process by which one class derives properties and methods from another to reduce redundancy.
Keyword: extends.
Relationship: "IS-A" (e.g., A Car is a Vehicle).

Types of Inheritance

  • Single Inheritance: Class A → Class B.
  • Multilevel Inheritance: Class A → Class B → Class C.
  • Hierarchical Inheritance: One parent, multiple children.
  • Multiple Inheritance: Not supported with classes in Java to avoid ambiguity.

The super Keyword

Refers to the immediate parent class.

A. Calling the Parent Constructor

super(arguments);

Crucial Rule: super() must be the very first statement in the child class’s constructor. If not explicit, Java calls default super() implicitly.

B. Accessing Parent Members

super.variableName or super.methodName(). Used when shadowing/overriding occurs.

Code Example (Multilevel Inheritance)

// 1. The Base Class
class Box {
   double l, h, w;
   Box(double l, double h, double w) {
       this.l = l; this.h = h; this.w = w;
   }
}

// 2. The Child Class
class BoxWeight extends Box {
   double weight;
   public BoxWeight(double l, double h, double w, double weight) {
       super(l, h, w); // Must initialize parent values first!
       this.weight = weight;
   }
}

// 3. The Grandchild Class
class BoxPrice extends BoxWeight {
   double cost;
   public BoxPrice(double l, double h, double w, double weight, double cost) {
       super(l, h, w, weight);
       this.cost = cost;
   }
}

Important Rules & "Gotchas"

  • Private Members: Not inherited directly. Accessible via public getters.
  • Static Methods: Inherited but cannot be overridden (Method Hiding).
  • The Object Class: The root of Java class hierarchy.
  • Constructor Order: Parent → Child → Grandchild.
  • Inlining with Final Methods: Compiler optimization replacing method calls with code. Only possible with final methods as they cannot be overridden.

Polymorphism

Polymorphism – The ability of an entity (method or object) to take multiple forms.

A common phrase used to describe this is: "One interface, multiple methods."

It reduces complexity by allowing us to use the same interface to perform different actions depending on the situation.

Types of Polymorphism:

A. Compile-time Polymorphism (Static Binding/Polymorphism)

This is achieved via Method Overloading. The compiler decides which method to call during compilation based on the arguments passed.

Rules for Method Overloading:

  • Must be in the same class.
  • Method names must be the same.
  • Parameter lists must be different (number of parameters or their types or their order).

Note: Changing only the return type is not sufficient to overload a method.

Automatic Type Conversion (Promotion): Java uses automatic type conversion in overload resolution if no exact match is found (when called with new constructor()) for method parameters.

Allowed promotion:
byte → short → int → long → float → double

Example: Overloaded Constructors, Functions (e.g., Box() and Box(double side)). Java picks the correct one based on whether you pass an argument when using new.

B. Runtime Polymorphism (Dynamic Binding)

This is achieved via Method Overriding. The decision of which method to run is made at runtime based on the actual object, not the reference variable.

Rules for Method Overriding:

  • Superclass Variable Referencing Subclass Object (dynamic method dispatch).
  • Method signature (name + parameters) must be exactly the same.
  • The version in the child class "hides" or replaces the version in the parent class.
Main Concept: Car car = new Lamborghini();
- Methods come from the Subclass (Lamborghini).
- Variables come from the Reference (Car).

Dynamic Method Dispatch (Runtime Polymorphism):

This is the mechanism Java uses to resolve calls to overridden methods at runtime rather than compile time.

  • Reference Type: Determines what methods can be accessed. (If the method isn't in the Parent class, you can't call it).
  • Object Type: Determines which implementation runs. (If the Child overrides it, the Child's version runs).

Upcasting and Downcasting

Aspect Upcasting (Widening) Downcasting (Narrowing)
Definition Converts subclass to superclass. Converts superclass to subclass.
Explicit/Implicit Implicit (No cast required). Explicit (Cast required).
Safety Safe, always valid. Unsafe, may throw ClassCastException. Always check with instanceof first!
Purpose Used for polymorphism. Used to access subclass-specific methods.
Example Animal a = new Dog(); Dog d = (Dog) a;

Comprehensive Code Example: Animals

This example demonstrates super(), Upcasting, Downcasting, and Polymorphism all in one. 

class Animal {
   String type;
   Animal() {
       type = "Unknown Animal";
       System.out.println("Animal constructor called.");
   }
   void eat() {
       System.out.println(type + " is eating.");
   }
   void sound() {
       System.out.println("Animal makes a sound");
   }
}

class Dog extends Animal {
   int legs;
   Dog() {
       super(); // Implicitly calls Animal constructor(not mandatory, defaults call auto)
       legs = 4;
       type = "Dog";
       System.out.println("Dog constructor called.");
   }

   @Override //just check if overridden (will show error if not)
   void sound() {
       System.out.println("Dog barks");
   }

   // Specific to Dog
   void bark() {
       System.out.println("The dog barks.");
   }
}

class Cat extends Animal {
   int lives;

   Cat() {
       super();
       lives = 9;
       type = "Cat";
       System.out.println("Cat constructor called.");
   }

   @Override
   void sound() {
       System.out.println("Cat meows");
   }

   // Specific to Cat
   void meow() {
       System.out.println("The cat meows.");
   }
}

public class Main {
   public static void main(String[] args) {
       // --- 1. Polymorphism & Upcasting ---
       // We use the Superclass reference (Animal) for different Subclass objects
       Animal myAnimal = new Dog();
       myAnimal.sound(); // Output: Dog barks (Dynamic Method Dispatch)
       
       // Variable access (shows variable hiding)
       System.out.println(myAnimal.type); //Unknown Animal

       myAnimal = new Cat();
       myAnimal.sound(); // Output: Cat meows (Flexibility!)

       // --- 2. The Limitation ---
       // myAnimal.meow(); // ERROR: The 'Animal' reference doesn't know about 'meow()'

       // --- 3. Downcasting to access specific methods ---
       if (myAnimal instanceof Cat) {
           Cat myCat = (Cat) myAnimal; // Explicit casting
           myCat.meow(); // Output: The cat meows.
           System.out.println(myCat.type); // Cat
       }
   }
}

Output:

Animal constructor called.
Dog constructor called.
Dog barks
Unknown Animal
Animal constructor called.
Cat constructor called.
Cat meows
The cat meows.
Cat

Flexibility: You can assign different subclass objects (e.g., Dog, Cat) to the same Animal reference, allowing for code generalization.

Early vs. Late Binding

  • Early Binding (Static Binding):
    Method calls are resolved at compile-time. Used with private, final, and static methods.
  • Late Binding (Dynamic Binding):
    Method calls are resolved at runtime based on the object type. Occurs with overridden methods, enabling runtime polymorphism.

Binding = deciding which method’s code will be executed when a method is called.

Inheritance vs. Polymorphism

Feature Inheritance Polymorphism
Focus "Is-a" relationship (Structure) Flexibility (Behavior)
Definition Subclass acquires properties of Superclass. Objects take multiple forms.
Mechanism extends keyword. Method Overloading / Overriding.
Timing Static (Compile-time structure). Dynamic (Runtime behavior).

Can Static Methods be Overridden? No.

Static methods belong to the class, not the object.

If you define a static method with the same name in a subclass, it is called Method Hiding, not overriding.

The compiler decides which static method to call based on the reference type (Compile-time polymorphism), not the actual object.

Abstract Classes & Interfaces

  • Abstract Classes: Cannot be instantiated, but their reference variables can hold subclass objects (e.g., Animal a = new Dog()).
  • Interfaces: Pure blueprints. They specify what a class must do, not how. They are the ultimate way to achieve "One interface, multiple methods."

Summary Checklist

  • Overloading: Same method name, different params (Compile-time).
  • Overriding: Same method signature in Child class (Runtime).
  • Dynamic Dispatch: Java runs the method based on the actual object, not the variable type.
  • Upcasting: Safe, used for generalization (Animal a = new Dog()).
  • Downcasting: Risky, used to access child-specific methods (Dog d = (Dog) a).

Java Packages & Access Modifiers

1. What is a Package?

A package is essentially a container for classes. It serves two main purposes:

  • Organization: It groups related classes together (modularity).
  • Namespace Management: It prevents naming conflicts.

Think of packages like folders on your computer.
You might have a file named Resume.docx in your "Work" folder and another Resume.docx in your "Personal" folder.
Because they are in different folders (packages), they don't conflict with each other.

Why do we need them?
If you create a class named List, it would normally conflict with Java’s built-in java.util.List. By putting your class inside your own package (e.g., mypackage.List), you avoid this collision.

2. Creating and Storing Packages

The Rules

  • First Line: The package statement must be the very first line of code in your Java file.
  • One Package: A class can belong to only one package.
  • File System Mapping: The package structure must match your directory structure exactly.

Code vs. Folder Structure

If you declare a package hierarchy, your folders must match it.

Code:

package java.awt.image;

Required Folder Structure (Windows example):

.../java/awt/image/

Note: You cannot rename a package simply by changing the code. You must also rename the actual directory where the .class files are stored.

3. Importing Packages

To use classes from another package, you must import them.

Syntax:

import pkg1.pkg2.ClassName; // Imports a specific class
import pkg1.pkg2.*;         // Imports ALL classes in that package

Key Details:

  • The Default Import: The java.lang package (containing String, Math, System) is imported automatically. You never need to manually import it.
  • Wildcards (*): Using import java.util.* imports all classes in that package. It might slightly increase compilation time, but it does not affect runtime performance.
  • Name Conflicts: If you import two packages that both have a class named Date (e.g., java.util and java.sql), you must use the fully qualified name to tell Java which one you mean:
    java.util.Date myDate = new java.util.Date();

4. How Java Finds Packages (Runtime)

When you run a program, how does Java know where to look for these packages? It searches in this order:

  1. Current Directory: By default, Java looks in the folder you are currently running from.
  2. CLASSPATH Variable: You can set an environment variable on your computer called CLASSPATH to tell Java where your libraries are stored.
  3. Command Line (-classpath): You can explicitly tell Java where to look when running a command:
    java -classpath C:\MyPrograms\Java mypackage.MyClass

5. Visibility & Access Modifiers

This is the most critical part of package logic. Packages act as a security wall.

The 4 Access Levels

  • private: Visible only within the same class. (Most restrictive)
  • default (no modifier): Visible to any class in the same package.
  • protected: Visible to the same package AND subclasses in other packages.
  • public: Visible everywhere. (Least restrictive)

private < default (same package) < protected (inherited in any package) < public (any)

Code Scenarios

Here is how the visibility rules work in practice.

Scenario A: The Parent Class (The Source)

package mypackage;
public class Parent {
    private int privateVar = 1;
    int defaultVar = 2;          // No modifier
    protected int protectedVar = 3;
    public int publicVar = 4;

    public void testAccess() {
        System.out.println(privateVar);  //  OK: Same Class
        System.out.println(defaultVar);     // OK: Same package
        System.out.println(protectedVar);   // OK: Same package
        System.out.println(publicVar);      // OK: Public
    }
}

Scenario B: Same Package (Subclass)

File: mypackage/Child.java

package mypackage;
public class Child extends Parent {
    public void testAccess() {
        // System.out.println(privateVar);  // ERROR: Private is hidden
        System.out.println(defaultVar);     // OK: Same package
        System.out.println(protectedVar);   // OK: Same package
        System.out.println(publicVar);      // OK: Public
    }
}

Scenario C: Different Package (Subclass)

File: otherpackage/DifferentPackageChild.java

package otherpackage;
import mypackage.Parent;

public class DifferentPackageChild extends Parent {
    public void testAccess() {
        // System.out.println(privateVar);  // ERROR
        // System.out.println(defaultVar);  // ERROR: Default is package-private
        System.out.println(protectedVar);   // OK: Accessible via inheritance
        System.out.println(publicVar);      // OK
    }
}

Scenario D: Different Package (Non-Subclass)

File: otherpackage/Stranger.java

package otherpackage;
import mypackage.Parent;

public class Stranger {
    public void testAccess() {
        Parent p = new Parent();
        // System.out.println(p.privateVar);   // ERROR
        // System.out.println(p.defaultVar);   // ERROR
        // System.out.println(p.protectedVar); // ERROR: Not a subclass
        System.out.println(p.publicVar);       // OK
    }
}

6. Important "Gotchas"

  • The Default Package: If you don't write package mypack;, your class goes into the "default package." Limitation: Classes in the default package cannot be imported by classes in other packages. Always use a package!
  • Interfaces: Interfaces can also be public or package-private (default). If an interface is not public, it cannot be implemented by classes outside its package.

7. Self-Check: Interview Q&A

Q1: What happens if two imported packages have classes with the same name?
A: The compiler will be silent until you actually try to use the class. Then, you must use the fully qualified name (e.g., java.sql.Date) to resolve the ambiguity.

Q2: Does importing packages.* slow down my program?
A: It may slow down compilation slightly, but it has zero effect on runtime performance.

Q3: Can a class be part of multiple packages?
A: No. A class can belong to only one package.

Q4: What is the -d option in the compiler?
A: It stands for "destination." When you run javac -d . MyClass.java, it tells the compiler to automatically create the folder structure (directories) that matches your package name.

Q5: Can I access a protected variable from a non-subclass in a different package?
A: No. protected allows access only to classes in the same package or subclasses (inheritance) in other packages.

Interfaces

1. What is an Interface?

An interface is a blueprint of a class's behavior. It is a strictly defined "contract" that specifies what a class must do, but not how it does it.

  • It is used to achieve Abstraction and support Multiple Inheritance.
  • The Rule: If a class "implements" an interface, it is legally bound to provide the actual code for every method defined in that interface.
Why do we need them? (The Diamond Problem)
Java does not support multiple inheritance with classes (e.g., Class C extends A, B) because of ambiguity: if both A and B have a run() method, which one does C inherit? This is known as the Diamond Problem.
The Solution: Java uses Interfaces.
1. A class can extend only one superclass.
2. But a class can implement multiple interfaces.
This allows unrelated classes (like Car and VideoGame) to implement the same behavior (like Startable), creating flexible polymorphism.

Difference in Method Resolution

class B {
   public void run() {
       System.out.println("B run");
   }
}

interface D {
   default void run() {
       System.out.println("D run");
   }
}

class A extends B implements D, E, F {
}

new A().run();  // Output: B run
// Precedence: Class > Interface > Abstract method

2. Key Rules & Syntax

  • Methods: Implicitly public and abstract. They generally have no body (unless using Java 8+ features).
  • Variables: Implicitly public, static, and final.
    Why? Interfaces cannot have instances, so they cannot hold "state." All variables effectively become global constants.
  • Constructors: Interfaces cannot have constructors because you cannot instantiate an interface directly.

Summary of Keywords:

  • Class → Class: extends
  • Class → Interface: implements
  • Interface → Interface: extends

3. Modern Interface Features (Java 8 & 9)

Originally, interfaces were 100% abstract. To keep up with modern development, Java 8 and 9 added features that allow interfaces to have some implementation code without breaking existing applications.

A. Default Methods (Java 8)

Allows you to add a method with a body using the default keyword.

Purpose: Backward compatibility. You can add a new feature to an interface without forcing every single class that implements it to break or be rewritten.

B. Static Methods (Java 8)

Utility methods that belong to the interface itself, not the implementing class.
Called via: InterfaceName.methodName().

C. Private Methods (Java 9)

Used to share common code between default and static methods inside the interface. They are hidden from the outside world.

Example: Modern Interface Syntax

interface Calculator {
    // 1. Default method (can be overridden by the class)
    // Calls a private helper method
    default int add(int a, int b) {
        return doOperation(a, b);
    }

    // 2. Static method (cannot be overridden, belongs to Interface)
    // Usage: Calculator.multiply(2, 3);
    static int multiply(int a, int b) {
        return doStaticOperation(a, b);
    }

    // 3. Private instance method (Helper for default methods)
    private int doOperation(int a, int b) {
        return a + b;
    }

    // 4. Private static method (Helper for static methods)
    private static int doStaticOperation(int a, int b) {
        return a * b;
    }
}

4. Conflict Resolution (The Diamond Problem)

When you implement multiple interfaces, you might run into a situation where two interfaces have a default method with the exact same name.

The Rule: If a conflict occurs, the compiler throws an error. You must override the method in your class and explicitly choose which version to use.

Example:

interface A { default void show() { System.out.println("A"); } }
interface B { default void show() { System.out.println("B"); } }

class C implements A, B {
    @Override
    public void show() {
        // Manually resolving the conflict
        A.super.show(); // Explicitly calls A's version
        // B.super.show(); // Or call B's version
    }
}

Nested Interfaces

An interface can be declared inside a class or another interface. Unlike top-level interfaces, these can be private, protected, or public.

Any interface declared inside a class is implicitly considered public static

class A {
    // Nested interface
    public interface NestedIF {

}

// B implements the nested interface using dot notation
class B implements A.NestedIF {
    public boolean isNotNegative(int x) {

    }
}

Abstraction

1. Abstract Classes (The Blueprint)

An abstract class acts as a generalized form. It defines the structure (the nature of the methods) but leaves specific implementation details to its subclasses.

  • The Rule: If a class contains even one abstract method, the class itself must be declared abstract.

Key Rules:

  • No Instantiation: You cannot create an object of an abstract class (new AbstractClass() is illegal).
  • Mixed Implementation: Can contain both abstract methods (no body) and concrete methods (with body).
  • Constructors: Yes, they can have constructors!
    Why? Even though you can't instantiate the abstract class, the constructor is used to initialize variables when a subclass object is created (chained via super()).
  • Subclass Responsibility: Any subclass must either implement all abstract methods of the parent OR be declared abstract itself.

Abstract vs. Concrete Features

Feature Can it be Abstract? Reason
Constructors NO Constructors build objects; you cannot build an abstract object.
Static Methods NO Static methods are called via the Class. If it were empty (abstract), nothing would execute.
Object References YES You can define a reference (Parent p = new Child();) for polymorphism.

3. What are Default Methods?

Default methods are methods defined in an interface with the default keyword.

  • These methods can have a body (i.e., an implementation) within the interface itself.
  • They provide a way for interfaces to add new methods without breaking existing implementing classes.
  • Any class that implements the interface can use the default method or override it with its own implementation.

4. Master Example: Putting It All Together

This example demonstrates:

  • Abstract Class (Vehicle): Defines "Identity" and shared state (model).
  • Interface (Electric): Defines a "Capability."
  • Concrete Class (Tesla): Combines them.
// 1. THE INTERFACE (The Capability)
interface Electric {
    String ENERGY_UNIT = "kWh"; // Constant

    void charge(); // Abstract method (what it must do)
    
    // Default method (Optional to override)
    default void checkBatteryStatus() {
        System.out.println("Checking battery health...");
    }
}

// 2. THE ABSTRACT CLASS (The Blueprint)
abstract class Vehicle {
    String model; // Instance variable (State)

    // Constructor: Used to initialize state via subclass!
    Vehicle(String model) {
        this.model = model;
    }

    // Abstract method: Subclass MUST implement this
    abstract void accelerate();

    // Concrete method: Shared behavior
    void stop() {
        System.out.println(model + " has stopped.");
    }
}

// 3. THE CONCRETE CLASS (The Real Object)
class Tesla extends Vehicle implements Electric {
    
    // Constructor matching the superclass
    Tesla(String model) {
        super(model); // Calls Vehicle's constructor
    }

    @Override
    void accelerate() {
        System.out.println(model + " accelerates silently (Electric drive).");
    }

    @Override
    public void charge() {
        System.out.println("Charging " + model + ". Unit: " + ENERGY_UNIT);
    }
}

// 4. MAIN CLASS
public class Main {
    public static void main(String[] args) {
        // Vehicle v = new Vehicle("Generic"); // ERROR! Cannot instantiate abstract class.

        // Polymorphism: Reference is Vehicle, Object is Tesla
        Vehicle myCar = new Tesla("Model S");
        
        myCar.accelerate(); // Calls Tesla's implementation
        myCar.stop();       // Calls Vehicle's shared implementation

        // To access Interface methods, we need a reference that knows about 'Electric'
        Tesla myTesla = (Tesla) myCar; 
        myTesla.charge();
        myTesla.checkBatteryStatus(); 
    }
}

5. Common Interview Q&A

Q: Can an abstract class implement an interface?
A: Yes.
1. The Standard Rule (Concrete Classes): If Class A is a concrete class, it must provide an implementation for every method declared in Interface B.
2. The Exception (Abstract Classes): If Class A is defined as abstract, it does not have to implement the methods of Interface B. Instead, it passes that responsibility down the line. The first "concrete" class that extends Class A will then be forced to implement all the missing methods.

Q: Can a class be both abstract and final?
A: No. abstract means "must be extended," and final means "cannot be extended." They are opposites.

Q: What is the "public scope" of a class?
A: It refers to all public methods/variables exposed to the user. It is the "face" of the class.

Q: What happens if I add a second abstract method to a Functional Interface?
A: If marked with @FunctionalInterface, the compiler throws an error. If not marked, it simply loses its status as a functional interface and cannot be used with Lambdas.

Exceptions

1. What is an Exception?

An exception is an abnormal condition (runtime error) that disrupts the normal flow of the program.

Handling: When an error occurs, an object representing the error is created and "thrown."

  • System-generated: By Java Runtime (e.g., dividing by zero).
  • Manually thrown: By your code using the throw keyword.

The 5 Keywords of Exception Handling

  • try – Monitor for errors
  • catch – Handle the error
  • throw – Manually create an error
  • throws – Declare an error might happen
  • finally – Clean up code that always runs

2. The Exception Hierarchy

All exceptions inherit from the Throwable class.

  • Error: Serious system problems you generally cannot catch (e.g., OutOfMemoryError, StackOverflowError).
  • Exception: Problems your program can and should handle.

3. Types of Exceptions: Checked vs. Unchecked

    } catch (IOException e) {

}

4. The try‑catch Block

Prevents the program from terminating abruptly.

  • A try block must have curly braces {}.
  • If an exception occurs, control jumps immediately to the matching catch. Remaining try statements are skipped.
  • If no exception, catch is skipped.

Multiple Catch Blocks

Specific exceptions must come before general ones. Example: catch ArithmeticException before Exception.

Multi‑Catch (Java 7+)

catch (ArithmeticException | NullPointerException e) {
    System.out.println("Handled: " + e);
}

Nested Try

You can nest try blocks. If inner try has no matching catch, the outer catch handles it.

5. All‑in‑One Example

public class AllInOneException {
    public static void main(String[] args) {
        try {
            System.out.println("--- Outer Try Start ---");
            try {
                String str = null;
                System.out.println(str.length()); // NullPointerException
                System.out.println("This won't print (Inner)");
            } catch (ArithmeticException | NullPointerException e) {
                System.out.println(">> Inner Multi-Catch handled: " + e);
            }
            System.out.println("--- Back in Outer Try ---");
            int[] numbers = {1, 2};
            System.out.println(numbers[5]); // ArrayIndexOutOfBoundsException
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println(">> Outer Specific Catch handled: Index Error");
        } catch (Exception e) {
            System.out.println(">> Outer General Catch handled: " + e);
        }
        System.out.println("Program continues safely...");
    }
}

6. The finally Block

Executes regardless of whether an exception occurred.

try {
    throw new RuntimeException("demo");
} finally {
    System.out.println("This always prints.");
}

The this Keyword

In Java, this is a reference variable that points to the current object.

1. Common Uses of this

A. Resolving Variable "Shadowing" (Ambiguity)

When a parameter (local variable) has the same name as an instance variable (class field), the local variable "shadows" or hides the instance variable. We use this to tell Java exactly which one we mean.

class Employee {
    String name; // Instance variable

    // The parameter 'name' shadows the instance variable 'name'
    Employee(String name) {
        this.name = name;  // this.name refers to the class field
    }

    void printName() {
        // Explicitly printing the current object's name
        System.out.println(this.name);
    }
}

B. Calling Constructors (Constructor Chaining)

You can use this() to call one constructor from another within the same class. This helps avoid rewriting code.

Rules:
  • this() must be the very first statement in the constructor.
  • It is used to reuse initialization logic.
class Box {
    int width, height;

    // Default constructor calls the parameterized one
    Box() {
        this(10, 20); 
        System.out.println("Default box created with size 10x20");
    }

    Box(int width, int height) {
        this.width = width;
        this.height = height;
    }
}

C. Returning the Current Object (Method Chaining)

We can return this from a method to allow "chaining" calls together (e.g., obj.add().subtract()). This is often called the Builder Pattern style.

class Calculator {
    int value = 0;

    Calculator add(int val) {
        this.value += val;
        return this; // Returns the current object so we can call another method on it
    }

    Calculator subtract(int val) {
        this.value -= val;
        return this;
    }

    void display() {
        System.out.println("Value: " + this.value);
    }
}

// Usage in Main:
// Calculator calc = new Calculator();
// calc.add(10).subtract(5).display(); // Output: Value: 5

D. Passing this as a Parameter

Sometimes you need to pass the current object into another method or class.

class Car {
    void display(Car c) {
        System.out.println("Processing Car object: " + c);
    }

    void show() {
        // Pass 'this' (the current car instance) to the display method
        this.display(this);  // pass object
    }
}

2. Important Rules & Limitations

  • No Static Access: You cannot use this inside static methods (like main). Static methods belong to the class, not a specific object, so there is no "current object" to refer to.
  • Constructor Order: If using this() or super() in a constructor, it must be the first line. You cannot do both in the same constructor.
              
              Dog() {
                // Error: 'this()' must be the first statement, and 'super()' is already called implicitly 
                super();   // Calls the superclass constructor 
                this();    // Error: 'this' must be the first statement 
                System.out.println("Dog constructor called"); 
            }

3. Constructors: Advanced Concepts

A. Default & Implicit Constructors

  • Every class has a constructor. If you don't write one, Java provides a default no-argument constructor.
  • Implicit super(): Every constructor automatically calls super() (the parent class constructor) as its first line, even if you don't write it.

B. The Copy Constructor

A copy constructor initializes a new object by copying values from an existing object of the same class.

class InterviewBit {
    String department;
    String service;

    // Standard Constructor
    InterviewBit(String dept, String serv) {
        this.department = dept;
        this.service = serv;
    }

    // Copy Constructor
    InterviewBit(InterviewBit ib) {
        this.department = ib.department; // Copying values
        this.service = ib.service;
    }
}

C. Inheritance Flow

When you create an object of a derived (child) class, the constructors execute in a specific order: Parent First, then Child.

class Base {
    Base() {
        System.out.println("Base Class Constructor Called");
    }
}

class Derived extends Base {
    Derived() {
        // implicit super() happens here
        System.out.println("Derived Class Constructor Called");
    }
}

// Output when creating new Derived():
// Base Class Constructor Called
// Derived Class Constructor Called

4. Multithreading Context

When implementing Runnable, this is often used to pass the current instance to the Thread constructor.

class NewThreads implements Runnable {
    Thread t;

    NewThreads() {
        // 'this' refers to the current NewThreads instance
        // We pass it to Thread so it knows which run() method to execute

The super Keyword

Definition: The super keyword is a reference variable used in a subclass (child) to refer to its immediate superclass (parent) object.

Why we need it:

  • Constructors: When you create an object of a Child class, the Parent class must be initialized first. Since constructors are not inherited, we use super(...) to call the parent's constructor explicitly.
  • Accessing Parent Methods: If a child class overrides a method (provides a specific implementation), you can still call the original parent version using super.methodName().
  • Accessing Parent Variables: If a child class defines a variable with the same name as the parent (Variable Shadowing), super.variableName allows you to access the parent's specific variable.
public class Main {
    public static void main(String[] args) {
        // Creating a BoxWeight object
        BoxWeight myBox = new BoxWeight(10, 20, 15, 50);

        // It has properties from both Parent and Child
        System.out.println("Volume: " + myBox.calculateVolume()); // Inherited from Parent
        System.out.println("Weight: " + myBox.weight);            // Specific to Child
    }
}

// 1. The Parent Class (Superclass)
class Box {
    double length;
    double height;
    double width;

    // Standard Constructor
    Box(double length, double height, double width) {
        this.length = length;
        this.height = height;
        this.width = width;
    }

    double calculateVolume() {
        return length * height * width;
    }
}

// 2. The Child Class (Subclass)
class BoxWeight extends Box {
    double weight;

    // CONSTRUCTOR:
    // In Java, super() must be the very first statement inside the constructor body.
    BoxWeight(double length, double height, double width, double weight) {
        // Pass arguments up to the Box class constructor
        super(length, height, width); 
        
        // Initialize the child-specific field
        this.weight = weight;         
    }
}

1. Static Method Restrictions

You cannot use this or super inside a static method.

2. The super Keyword Rules

super() (Constructor Call):

  • It calls the constructor of the immediate superclass.
  • The Golden Rule: super() must always be the first statement in the subclass constructor. This ensures the parent is fully initialized before the child tries to use any inherited data.
  • If you do not write super(), the Java compiler automatically inserts a default no-argument super() for you.

super.method():

Calls a method from the parent class (useful when the method was overridden in the child).

super.variable:

Accesses a variable in the parent class that has been shadowed (hidden) by a variable of the same name in the child class.

3. Default Constructor Behavior

Every constructor in Java has a call to another constructor as its first line. If you don't type it, the compiler adds super().

this() vs super():

  • this() calls a constructor within the same class.
  • super() calls a constructor in the parent class.
  • Conflict: Since both this() and super() must be the first statement, a single constructor cannot contain both. You must choose one.

The static Keyword

In Java, static means that a member (variable or method) belongs to the class itself, not to any specific instance (object) of that class.

  • Without static: You need an object to access the member (e.g., obj.method()).
  • With static: You can access it directly using the class name (e.g., ClassName.method()).

1. The main Method Explained

public static void main(String[] args)
  • public: Access modifier allowing the JVM (code outside the class) to call the method.
  • static: Allows the JVM to call main without creating an instance of the class first.
  • void: The method does not return a value.
  • String[] args: Stores command-line arguments passed to the program.

2. Static Variables (Class Variables)

Static variables are shared among all instances of a class. They are essentially global variables for that class.

  • Memory: Allocation happens only once when the class is loaded.
  • Behavior: Changing a static variable in one place affects it for all objects.
class Mobile {
    static String brand = "Samsung"; // Shared by all objects
    String model;                    // Unique to each object

    public void show() {
        System.out.println(brand + " : " + model);
    }
    
    public static void main(String[] args) {
        Mobile m1 = new Mobile();
        m1.model = "S21";
        
        Mobile m2 = new Mobile();
        m2.model = "S10";
        
        Mobile.brand = "Apple"; // Changed for EVERYONE
        
        m1.show(); // Output: Apple : S21
        m2.show(); // Output: Apple : S10
    }
}

3. Static Blocks

A static block is used to initialize static variables. It runs exactly once when the class is first loaded into memory.

class StaticTest {
    static int a = 3;
    static int b;

    // Static block
    static {
        System.out.println("Static block initialized.");
        b = a * 4;
    }

    public static void main(String[] args) {
        System.out.println("Value of b: " + b); // Output: 12
    }
}

4. Static Methods

Static methods belong to the class. They are often used for utility functions (like Math.sqrt()).

Rules of Static:
  • Cannot access instance variables directly.
  • Cannot use this or super.
  • Can only call other static methods directly.

Workaround: Accessing Instance Data

class Human {
    String message = "Hello World"; // Instance variable

    public static void display(Human h) {
        // Valid: We are telling the static method WHICH object to look at
        System.out.println(h.message); 
    }
}

5. Method Overloading vs. Overriding

  • Overloading: Yes, you can overload static methods.
  • Overriding: No. Static methods are bound at compile time (Static Binding).
  • Method Hiding: A subclass can define a static method with the same signature, but it hides the parent's version rather than overriding it.

The final Keyword

In Java, final is used to prevent change. It applies to Variables, Methods, and Classes.

1. Final Variables (Constants)

Once a final variable is initialized, its value cannot be changed.

  • Initialization: Must be done during declaration or in the constructor.
  • Naming: Constants (static final) use UPPER_CASE.
  • Local Variables: Prevents reassignment within a function.
  • Method Arguments: You cannot change the parameter value inside the method.
  • Interface Variables: Implicitly public static final.
public class FinalDemo {
    static final double PI = 3.14159; // Constant
    final int val;                    // Blank Instance Final

    FinalDemo(int v) { this.val = v; } // Initialized in Constructor

    void demo(final int arg) {
        final int local = 10;
        // arg = 20; // Error
        System.out.println(val + " " + PI + " " + arg + " " + local);
    }
    // if final value is static and uninitialized, it must be initialized in static block
    // instance final variables must be initialized in constructor
    // static block cant initialize instance final variables
    
}
Reference vs. State:

final locks the reference (the leash), not the object itself (the dog).

  • Allowed: Modifying internal data (e.g., list.add("item")).
  • Forbidden: Pointing the variable to a new object (e.g., list = new ArrayList()).

2. Final Methods (Prevent Overriding)

A final method cannot be overridden by a subclass. This ensures consistency and allows for compiler optimizations like "inlining".

class Parent {
    final void show() {
        System.out.println("This behavior is locked.");
    }
}

3. Final Classes (Prevent Inheritance)

A final class cannot be extended. Real-world example: java.lang.String is final to ensure security and immutability.

final class SecureBox { }
// class HackBox extends SecureBox { } // Error

// NOTE: final class-> cant be inherited but can be instantiated
// private constructor-> cant be instantiated & inherited (normally)

4. Advanced Concepts

A. Effectively Final

Variables used in anonymous inner classes or lambdas must be final or "effectively final" (never changed after initialization).

B. Abstract and Final

A class cannot be both abstract and final. They are opposites.

C. Immutable Class Recipe

  1. Mark the class final.
  2. Mark all fields private and final.
  3. Provide only getter methods (no setters).
  4. Initialize everything via the constructor.
